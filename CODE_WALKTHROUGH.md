## 1. Project Structure

```
DX-Ball/
├── CMakeLists.txt      build description (what to compile, what to link)
├── build.sh            one-command build helper script
├── build/              generated by CMake — ignored by version control
└── src/
    ├── levels.h        pure data: the three level layouts
    ├── game.h          shared types, constants, and function declarations
    ├── game.cpp        all game logic and all OpenGL rendering (~820 lines)
    ├── main.cpp        entry point: GLUT window + callback registration
    ├── sound.h         public interface for the audio module
    └── sound.cpp       macOS AudioToolbox sound synthesis
```

The game is deliberately split into a tiny `main.cpp` (plumbing) and a large
`game.cpp` (everything else).  `sound.cpp` is isolated so the audio code never
leaks into game logic.  `levels.h` is pure data with no logic, making it easy
to add new levels without touching any other file.

## 2. CMakeLists.txt — Build System

```cmake
cmake_minimum_required(VERSION 3.20)
```
Tells CMake "I need at least version 3.20".  Older CMake versions may lack
features or module fixes used here.

```cmake
project(BrickBreaker LANGUAGES CXX)
```
Names the project "BrickBreaker" and declares that only C++ source files will
be compiled (no C, no Fortran).

```cmake
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
```
Forces C++17.  `std::clamp`, structured bindings, and `std::string` niceties
used in the code all require at least C++17.  `REQUIRED ON` makes CMake error
out (rather than silently downgrade) if the compiler cannot do C++17.

```cmake
find_package(OpenGL REQUIRED)
```
Asks CMake to locate the system OpenGL library.  On macOS this finds
`OpenGL.framework`; on Windows it finds `opengl32.lib`.  Creates the import
targets `OpenGL::GL` and `OpenGL::GLU` that are used later in
`target_link_libraries`.

```cmake
if(APPLE)
    find_package(GLUT REQUIRED)
else()
    find_package(FreeGLUT REQUIRED)
endif()
```
On macOS the system ships a built-in `GLUT.framework` (inside the Xcode
Command Line Tools SDK) which provides everything the game needs.  On
Windows/Linux we rely on the third-party FreeGLUT library instead, because
Apple's GLUT is macOS-only.

```cmake
add_executable(BrickBreaker
    src/main.cpp
    src/game.cpp
    src/sound.cpp
)
```
Declares the final executable named "BrickBreaker" and lists every `.cpp` file
that must be compiled and linked together.  Header files (`.h`) do **not** go
here — they are pulled in automatically via `#include` directives.

```cmake
target_include_directories(BrickBreaker PRIVATE src)
```
Tells the compiler to look inside the `src/` folder when resolving `#include`
paths.  This is why `#include "game.h"` works even though the file lives at
`src/game.h`.

```cmake
if(APPLE)
    target_link_libraries(BrickBreaker PRIVATE
        GLUT::GLUT OpenGL::GL "-framework AudioToolbox")
else()
    target_link_libraries(BrickBreaker PRIVATE
        FreeGLUT::freeglut OpenGL::GL OpenGL::GLU)
endif()
```
Specifies which libraries to link into the final executable.
- `GLUT::GLUT` / `FreeGLUT::freeglut` — window management, input callbacks,
  bitmap fonts, the main loop.
- `OpenGL::GL` — the actual GPU drawing commands (`glColor3f`, `glBegin`, etc.).
- `OpenGL::GLU` — higher-level OpenGL utilities (used only on non-Apple because
  on macOS GLU is already bundled inside the OpenGL framework).
- `"-framework AudioToolbox"` — macOS Core Audio framework used in `sound.cpp`
  to synthesise and play game sounds.

```cmake
if(MSVC)
    target_compile_options(BrickBreaker PRIVATE /W3)
endif()
```
On Microsoft's compiler, enable warning level 3.  Ignored on clang/GCC.

```cmake
if(APPLE)
    target_compile_definitions(BrickBreaker PRIVATE GL_SILENCE_DEPRECATION)
endif()
```
Apple marked the entire OpenGL and GLUT API as "deprecated" in macOS 10.14.
Without this define the build is flooded with thousands of deprecation warnings
that make real errors invisible.  The define silences those warnings; the API
still works fine.

```cmake
if(WIN32)
    add_custom_command(TARGET BrickBreaker POST_BUILD ...)
endif()
```
After a successful Windows build, copies `freeglut.dll` next to the `.exe` so
the game can find it at runtime.  `POST_BUILD` means "run this shell command
after the link step".  `$<TARGET_FILE:FreeGLUT::freeglut>` is a CMake generator
expression that expands to the full path of the DLL at build time.

## 3. build.sh — Build Script

```bash
#!/usr/bin/env bash
set -e
```
`#!/usr/bin/env bash` tells the OS which interpreter to use.  `set -e` makes
the script abort immediately if any command returns a non-zero exit code —
so a failed configure step won't silently proceed to a broken build.

```bash
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
```
Resolves the directory that contains this script, regardless of where the user
calls it from.  `$0` is the script's path; `dirname` strips the filename to get
the directory; `cd ... && pwd` canonicalises it to an absolute path.  This
ensures `cmake -S .` always points at the project root.

```bash
CMAKE=$(python3 -c "import cmake; import os; print(os.path.join(cmake.CMAKE_BIN_DIR, 'cmake'))" 2>/dev/null || command -v cmake)
```
Attempts to use the `cmake` binary that was installed via `pip3 install cmake
--user` (which is how CMake was obtained on this Mac since Homebrew had
permission issues).  If that fails — because cmake is installed system-wide
instead — falls back to whatever `cmake` is on `$PATH`.

```bash
"$CMAKE" -S . -B build
"$CMAKE" --build build --parallel
```
Two-step CMake workflow:
1. `-S . -B build` — **configure**: reads `CMakeLists.txt`, detects compilers
   and libraries, writes Makefiles (or Ninja files) into the `build/` folder.
   Re-running this is cheap and harmless; CMake only regenerates what changed.
2. `--build build --parallel` — **build**: invokes the native build tool (make,
   Ninja, etc.) to compile and link.  `--parallel` uses all available CPU cores.

## 4. levels.h — Level Data

```cpp
constexpr int ROWS       = 6;
constexpr int COLS       = 10;
constexpr int NUM_LEVELS = 3;
```
The grid is always 6 rows × 10 columns = 60 brick slots per level.  `constexpr`
means the value is computed at compile time and can be used in array sizes,
switch cases, and template parameters.

```cpp
enum Tile { O=0, N=1, S=2 };
```
Three tile codes: O = empty, N = Normal brick (1 hit), S = Strong brick (2 hits).
Using an enum instead of raw integers makes the level layouts below readable.

```cpp
constexpr Tile LEVEL1[ROWS * COLS] = {
    N, N, N, N, N, N, N, N, N, N,
    N, O, O, O, O, O, O, O, O, N,
    ...
};
```
Each level is a flat array of 60 tiles, written row-by-row so the layout matches
what you see on screen.  The top row of the array corresponds to the top row of
bricks on screen.  `constexpr` means the data lives in read-only memory (text
segment), not on the stack.

```cpp
constexpr const Tile* ALL_LEVELS[NUM_LEVELS] = { LEVEL1, LEVEL2, LEVEL3 };
```
A pointer array so `loadLevel(n)` can say `ALL_LEVELS[n]` instead of a switch
statement.  Adding a new level only requires defining the data array and adding
it here.

## 5. game.h — Types, Constants, and Declarations

### World dimensions

```cpp
constexpr float WORLD_W = 800.0f;
constexpr float WORLD_H = 600.0f;
```
The logical coordinate space is 800 × 600 units.  All positions, sizes, and
velocities are expressed in these "world units".  The OpenGL projection matrix
(set in `onReshape`) maps this space to whatever the actual window size is, so
the game looks correct even when the window is resized.

### Ball constants

```cpp
constexpr float BALL_SPEED     = 300.0f;   // starting speed (units/second)
constexpr float BALL_SPEED_MAX = 600.0f;   // cap
constexpr float BALL_RAMP      =   6.0f;   // units/sec added every second
```
The ball starts at 300 u/s and accelerates by 6 u/s every second of play time
until capped at 600 u/s.  This ramp creates increasing tension as a round
progresses.

### Paddle constants

```cpp
constexpr float PAD_SPEED     = 400.0f;
constexpr float PAD_W_DEFAULT = 100.0f;
constexpr float PAD_W_WIDE    = 150.0f;
constexpr float PAD_W_SHRINK  =  60.0f;
```
The paddle moves at 400 u/s under keyboard control.  Its width changes with
perks: 100 (normal) → 150 (Wide perk) or 60 (Shrink perk).

### Perk / drop constants

```cpp
constexpr float PERK_DURATION = 10.0f;   // seconds a timed perk lasts
constexpr float DROP_VY       = -150.0f; // pixels/sec, negative = downward
constexpr float DROP_W        = 24.0f;
constexpr float DROP_H        = 14.0f;
```
A perk capsule falls at 150 u/s (positive Y is up in this coordinate system,
so negative vy means moving down).

### Enums

```cpp
enum class BrickType { NONE, NORMAL, STRONG };
```
`NONE` bricks are invisible placeholders (the slot exists but is empty).
`NORMAL` dies in one hit; `STRONG` needs two.

```cpp
enum class GameState { MENU, HELP, WAITING, PLAYING, PAUSED, GAME_OVER, YOU_WIN };
```
A strict state machine.  Every frame, `gameUpdate` and `gameDraw` check this
value to know what to simulate or draw.

```cpp
enum class InputSrc { KEYBOARD, MOUSE };
```
Tracks which input device last moved the paddle.  Mouse input takes over the
paddle's X position directly; keyboard input uses velocity-based movement.
The last-used source wins.

### Structs

```cpp
struct Ball   { float x, y, vx, vy, size; };
```
`x, y` — position of the ball's top-left corner (the ball is a square).
`vx, vy` — velocity in world units per second.
`size` — side length of the square (12 px).

```cpp
struct Paddle { float x, y, w, h; };
```
`x, y` — position of the paddle's bottom-left corner.
`w, h` — width and height.  `h` is fixed at 15; `w` changes with perks.

```cpp
struct Brick  { BrickType type; int hp; bool alive; float x, y, w, h; };
```
`alive` is the primary "does this brick exist?" flag.  `hp` counts remaining
hits (1 or 2).  Both `type` and the stored position are needed at draw time to
choose colour.

```cpp
struct Drop   { PerkType type; float x, y, vy; bool alive; };
```
A falling perk capsule.  `vy` is always `DROP_VY` (-150); it is stored per-drop
so a future feature could vary speeds.

## 6. main.cpp — Entry Point

```cpp
#ifdef _WIN32
#  include <windows.h>
#endif
```
`windows.h` must be included before any OpenGL header on Windows, because
OpenGL headers on Windows depend on types defined there.  The guard ensures
this line is compiled only on Windows.

```cpp
#ifdef __APPLE__
#  include <GLUT/glut.h>
#else
#  include <GL/glut.h>
#endif
```
Apple ships GLUT as a framework whose header lives at `<GLUT/glut.h>`.
FreeGLUT and every other platform put it at `<GL/glut.h>`.  This guard picks
the right path automatically at compile time.

```cpp
glutInit(&argc, argv);
```
Initialises the GLUT library.  Must be called before any other GLUT function.
Parses and removes any GLUT-specific command-line arguments.

```cpp
glutInitDisplayMode(GLUT_DOUBLE | GLUT_RGB);
```
Requests a **double-buffered** window (one buffer is shown while the other is
being drawn into, preventing flicker) with an **RGB** colour model (no alpha
channel needed).

```cpp
glutInitWindowSize(800, 600);
glutCreateWindow("Brick Breaker");
```
Opens an 800 × 600 pixel window titled "Brick Breaker".  This matches the
`WORLD_W × WORLD_H` logical size chosen in `game.h`.

```cpp
glutDisplayFunc(displayFunc);
```
Registers `displayFunc` as the **display callback** — GLUT calls it every time
it decides the window needs to be redrawn (i.e., when `glutPostRedisplay()` has
been called).  `displayFunc` just forwards to `gameDraw()`.

```cpp
glutTimerFunc(16, timerFunc, 0);
```
Asks GLUT to call `timerFunc` after 16 milliseconds.  This starts the fixed
timestep game loop.

```cpp
static void timerFunc(int /*value*/)
{
    const float dt = 16.0f / 1000.0f;   // 16 ms in seconds
    gameUpdate(dt);
    glutPostRedisplay();
    glutTimerFunc(16, timerFunc, 0);     // re-register for next tick
}
```
`timerFunc` is the heartbeat of the game.  Every 16 ms (~62.5 fps):
1. It calls `gameUpdate(0.016)` to advance the simulation by one fixed step.
2. It calls `glutPostRedisplay()` to tell GLUT "the world changed, please call
   the display callback soon".
3. It re-registers itself for the next 16 ms so the loop continues forever.

Using a **fixed timestep** (always 0.016 s regardless of actual frame time)
makes physics deterministic — the ball follows the same path every run.

```cpp
glutKeyboardFunc(onKeyboard);
glutSpecialFunc(onSpecial);
glutSpecialUpFunc(onSpecialUp);
glutMouseFunc(onMouse);
glutPassiveMotionFunc(onPassiveMotion);
glutReshapeFunc(onReshape);
```
Registers all input callbacks.  "Special" keys are non-ASCII keys like arrow
keys, F-keys, etc.  "Passive" motion means mouse movement with no button held.
`ReshapeFunc` is called when the window is resized.

```cpp
gameInit();
onReshape(800, 600);
```
Initialises game state, then immediately calls `onReshape` to set up the OpenGL
projection matrix before the first frame.  Without this, the first frame might
draw with an uninitialised projection.

```cpp
glutMainLoop();
```
Hands control to GLUT forever.  GLUT now drives the program — it calls the
registered callbacks at the right times.  This function never returns under
normal circumstances; the game exits via `std::exit(0)` in the input callbacks.

## 7. game.cpp — Game Logic and Rendering

### 7.1  Includes and Global State

```cpp
#include "game.h"
#include "sound.h"
```
Every game function and constant lives in these two headers.  Because both are
included here, `game.cpp` can call `soundPlayBrickBreak()` etc. directly.

```cpp
static Ball   ball;
static Paddle paddle;
static Brick  bricks[MAX_BRICKS];   // 60 slots (ROWS × COLS)
static Drop   drops[MAX_DROPS];     // 16 simultaneous falling perks
```
`static` at file scope means these variables are private to this translation
unit — no other `.cpp` file can see them.  They persist for the lifetime of the
program (not destroyed between function calls).

```cpp
static bool specialDown[256] = {};
```
A lookup table indexed by GLUT special-key codes.  Set to `true` when a key is
pressed, `false` when released.  `gameUpdate` reads it every tick to know
whether the left/right arrow key is currently held.  The `{}` zero-initialises
the whole array.

```cpp
static float bestTime = -1.0f;
```
`-1` is used as a sentinel meaning "no best time recorded yet" (a valid time is
always ≥ 0).

### 7.2  Low-Level Drawing Helpers

```cpp
static bool aabbOverlap(float ax, float ay, float aw, float ah,
                        float bx, float by, float bw, float bh)
{
    return ax < bx + bw && ax + aw > bx &&
           ay < by + bh && ay + ah > by;
}
```
**Axis-Aligned Bounding Box (AABB) overlap test.**  Two rectangles overlap if
and only if they do *not* miss on any axis.  Equivalent to:
- Left edge of A is to the left of right edge of B, AND
- Right edge of A is to the right of left edge of B, AND
- same in Y.
Used for every collision check in the game (ball-brick, ball-paddle, drop-paddle).

```cpp
static void drawRect(float x, float y, float w, float h)
{
    glBegin(GL_QUADS);
        glVertex2f(x,     y);       // bottom-left
        glVertex2f(x + w, y);       // bottom-right
        glVertex2f(x + w, y + h);   // top-right
        glVertex2f(x,     y + h);   // top-left
    glEnd();
}
```
The lowest-level primitive.  `glBegin(GL_QUADS)` tells OpenGL that subsequent
vertex calls form four-vertex polygons.  Vertices are given in counter-clockwise
order (bottom-left → bottom-right → top-right → top-left).  `glEnd()` finishes
the quad.  The colour used is whatever was last set with `glColor3f`.

```cpp
static void drawBevel(float x, float y, float w, float h,
                      float r, float g, float b, float E = 3.0f)
{
    glColor3f(r * 0.45f, g * 0.45f, b * 0.45f);  // dark shadow layer
    drawRect(x, y, w, h);

    glColor3f(min(1, r+0.28), min(1, g+0.28), min(1, b+0.28)); // highlight
    drawRect(x, y + E, w - E, h - E);

    glColor3f(r, g, b);                            // base colour face
    drawRect(x + E, y + E, w - 2*E, h - 2*E);
}
```
Simulates a 3-D bevel effect with three layered rectangles:
1. A darkened full-size rectangle as the "shadow" (bottom-right edge).
2. A lighter, slightly inset rectangle as the "highlight" (top-left edge).
3. The base-colour face in the centre.

Because OpenGL draws in submission order, each new rectangle paints over the
previous one.  The visible result is: a thin dark border at the bottom and
right, a thin bright border at the top and left, and the main colour in the
middle — exactly like a raised button.

```cpp
static void drawText(float x, float y, const std::string& s, void* font)
{
    glRasterPos2f(x, y);
    for (char c : s)
        glutBitmapCharacter(font, c);
}
```
`glRasterPos2f` sets the raster position — the cursor where bitmap characters
will be drawn.  `glutBitmapCharacter` draws one character glyph and advances
the raster position by the character's width.  The loop draws the entire string
left-to-right.

```cpp
static float textWidth(const std::string& s, void* font)
{
    float w = 0.0f;
    for (char c : s)
        w += (float)glutBitmapWidth(font, (unsigned char)c);
    return w;
}
```
`glutBitmapWidth` returns the advance width of a single character in pixels for
the given GLUT bitmap font.  Summing these gives the total rendered width of the
string, which is used by `drawTextCentered` to calculate the starting X
position so the text is visually centred around a given point.

### 7.3  Random Numbers and Ball Speed Helpers

```cpp
static float randf01()
{
    return (float)std::rand() / (float)RAND_MAX;
}
```
Returns a uniform random float in [0, 1).  `std::rand()` is seeded by the
default seed (1), meaning every run is identical — useful for debugging, and
acceptable for a simple arcade game.

```cpp
static float effectiveBallSpeed()
{
    float s = ballSpeedNow;
    if (fastTimer > 0.0f) s *= 1.4f;   // Fast Ball perk: +40%
    if (slowTimer > 0.0f) s *= 0.7f;   // Slow Ball perk: -30%
    return s;
}
```
`ballSpeedNow` is the base speed after the time-based ramp.  Perk multipliers
are applied on top.  Both perks cannot be active simultaneously (applying one
cancels the other), but the timer logic cancels old timers correctly.

```cpp
static void rescaleBallSpeed(float target)
{
    float mag = std::sqrt(ball.vx * ball.vx + ball.vy * ball.vy);
    if (mag < 0.001f) return;     // avoid division by zero when ball is still
    ball.vx = ball.vx / mag * target;
    ball.vy = ball.vy / mag * target;
}
```
Preserves the ball's direction (angle) while changing only its speed.  Dividing
by `mag` normalises the velocity vector to length 1, then multiplying by
`target` scales it to the desired speed.  The guard `mag < 0.001` prevents a
crash when the ball is stationary (WAITING state).

### 7.4  Ball Reset and Launch

```cpp
static void resetBall()
{
    ball.size = 12.0f;
    ball.x    = paddle.x + paddle.w / 2.0f - ball.size / 2.0f;
    ball.y    = paddle.y + paddle.h + 1.0f;
    ball.vx = ball.vy = 0.0f;
    state = GameState::WAITING;
}
```
Places the ball centred above the paddle, 1 unit above its top edge.  Setting
velocity to zero and state to WAITING means the ball "sticks" to the paddle
until the player launches it.

```cpp
static void launchBall()
{
    if (state != GameState::WAITING) return;
    float angle = 25.0f * PI / 180.0f;   // 25 degrees from vertical
    float s     = effectiveBallSpeed();
    ball.vx = s * std::sin(angle);         // horizontal component
    ball.vy = s * std::cos(angle);         // vertical component (upward)
    state   = GameState::PLAYING;
}
```
Converts the launch angle (25° off vertical) into X and Y velocity components
using trigonometry.  `sin` gives the horizontal component and `cos` the
vertical one because the angle is measured from the Y-axis (vertical), not
the X-axis.  A 25° angle gives an initial trajectory that looks natural and
avoids boring straight-up launches.

### 7.5  Perk Drops — Spawning and Applying

```cpp
static void spawnDrop(float cx, float cy)
{
    if (randf01() > 0.25f) return;   // 75% chance: no drop at all
    ...
    float r = randf01();
    PerkType t;
    if      (r < 0.20f) t = PerkType::EXTRA_LIFE;
    else if (r < 0.45f) t = PerkType::WIDE_PADDLE;
    else if (r < 0.65f) t = PerkType::FAST_BALL;
    else if (r < 0.85f) t = PerkType::SLOW_BALL;
    else                t = PerkType::SHRINK_PADDLE;
}
```
A two-stage random decision: first decide *whether* to drop at all (25% chance),
then decide *which* perk using a weighted probability table.  Positive perks
(extra life, wide paddle, etc.) have higher combined probability (85%) than the
negative perk (shrink paddle, 15%).

```cpp
static void updateDrops(float dt)
{
    for (int i = 0; i < MAX_DROPS; ++i) {
        Drop& d = drops[i];
        if (!d.alive) continue;
        d.y += d.vy * dt;                  // apply gravity (downward)
        if (d.y + DROP_H < 0.0f) {         // fell off bottom — disappear
            d.alive = false; continue;
        }
        if (aabbOverlap(...paddle...)) {   // caught by paddle
            applyPerk(d.type);
            d.alive = false;
        }
    }
}
```
Each active drop moves downward every frame.  Two termination conditions:
1. It falls below the bottom of the screen (wasted).
2. Its bounding box overlaps the paddle (collected).

```cpp
static void applyPerk(PerkType t)
{
    switch (t) {
        case WIDE_PADDLE:
            paddle.w    = PAD_W_WIDE;
            wideTimer   = PERK_DURATION;
            shrinkTimer = 0.0f;    // cancel the opposite perk
            break;
        ...
        case FAST_BALL:
            fastTimer = PERK_DURATION;
            slowTimer = 0.0f;      // cancel slow
            rescaleBallSpeed(effectiveBallSpeed());  // immediately apply speed
            break;
    }
    paddle.x = std::clamp(paddle.x, 0.0f, WORLD_W - paddle.w);
}
```
Each perk is applied immediately.  Timed perks set a countdown timer.  Opposite
perks cancel each other (you can't be Wide and Shrunk at the same time).
After changing paddle width the paddle position is clamped so it can't end up
partially off-screen.

### 7.6  Level Loading

```cpp
void loadLevel(int n)
{
    const float SLOT_W    = 80.0f;   // each brick cell is 80 units wide
    const float SLOT_H    = 24.0f;   // each cell is 24 units tall
    const float BRICK_W   = 76.0f;   // brick is 4 units narrower than its slot
    const float BRICK_H   = 20.0f;   // brick is 4 units shorter than its slot
    const float BRICK_TOP = 560.0f;  // Y of the topmost row
```
The grid slots are 80 × 24.  Each brick is slightly smaller (76 × 20), leaving
4-unit gaps between bricks on all sides so you can visually distinguish them.

```cpp
    b.x = c * SLOT_W + 2.0f;
    b.y = BRICK_TOP - (float)r * SLOT_H - BRICK_H;
```
`c * 80 + 2` places the brick 2 units inside the left edge of its column.
`BRICK_TOP - r * 24 - 20` places it: start at the top (560), shift down by
`r` rows (row 0 = topmost), then shift down by the brick height so that Y refers
to the bottom of the brick (OpenGL's Y-origin is at the bottom-left).

static void startNewRun()

### 7.8  gameUpdate — The Simulation Tick

Called every 16 ms with `dt = 0.016` (seconds).

```cpp
if (state == MENU || state == HELP || state == PAUSED || ...)
    return;
```
Early exit for all non-simulated states.  Physics only runs in WAITING and
PLAYING.

```cpp
if (lastInput == InputSrc::KEYBOARD) {
    if (specialDown[GLUT_KEY_LEFT])  paddle.x -= PAD_SPEED * dt;
    if (specialDown[GLUT_KEY_RIGHT]) paddle.x += PAD_SPEED * dt;
    paddle.x = std::clamp(paddle.x, 0.0f, WORLD_W - paddle.w);
}
```
Multiplying velocity by `dt` makes movement **frame-rate independent** — the
paddle moves the same distance per real second regardless of how large `dt` is.
`clamp` prevents the paddle from leaving the screen edges.

```cpp
if (state == GameState::WAITING) {
    ball.x = paddle.x + paddle.w / 2.0f - ball.size / 2.0f;
    ball.y = paddle.y + paddle.h + 1.0f;
    ...
    return;
}
```
In WAITING the ball is glued to the paddle.  Drops and perk timers still
update so a caught perk can expire while waiting to launch.

**Speed ramp:**
```cpp
float newBase = std::min(BALL_SPEED_MAX, BALL_SPEED + BALL_RAMP * elapsedTime);
if (std::fabs(newBase - ballSpeedNow) > 0.001f) {
    ballSpeedNow = newBase;
    rescaleBallSpeed(effectiveBallSpeed());
}
```
The base speed grows linearly with `elapsedTime` (in seconds): 300 + 6 × t, up
to 600.  When the target speed changes, `rescaleBallSpeed` adjusts the ball's
current velocity vector to the new magnitude without changing direction.

**Wall collisions:**
```cpp
bool wallHit = false;
if (ball.x < 0.0f) {
    ball.x  = 0.0f;          // push ball back inside the boundary
    ball.vx = std::fabs(ball.vx);  // force rightward velocity
    wallHit = true;
}
```
`fabs` is used instead of negation (`vx = -vx`) because the ball could have
penetrated the wall across multiple frames (if dt is large or the ball is fast).
Using `fabs` guarantees the direction is correct regardless of the current sign.
The same logic applies to all four walls.  A single sound plays at most once per
tick (using the `wallHit` flag) even if the ball hits a corner.

**Paddle collision:**
```cpp
float normHit = (ballCX - paddle.x) / paddle.w;   // 0.0 = left edge, 1.0 = right
normHit = std::clamp(normHit, 0.0f, 1.0f);
float angle = (normHit - 0.5f) * (120.0f * PI / 180.0f);
// normHit=0   → angle = -60° (sharp left)
// normHit=0.5 → angle = 0°   (straight up)
// normHit=1   → angle = +60° (sharp right)
ball.vx = s * std::sin(angle);
ball.vy = s * std::cos(angle);
ball.y  = paddle.y + paddle.h;   // snap ball above paddle (resolve penetration)
```
This is the angle-based paddle reflection used in classic Breakout/DX-Ball
games.  Where the ball hits on the paddle determines the outgoing angle.
Hitting near the edges sends the ball at a steep angle; hitting the centre
sends it nearly straight up.  This gives the player control over ball direction.

**Brick collision:**
```cpp
float ox = std::min(ball.x + ball.size, b.x + b.w) - std::max(ball.x, b.x);
float oy = std::min(ball.y + ball.size, b.y + b.h) - std::max(ball.y, b.y);
if (ox < oy) ball.vx = -ball.vx;   // horizontal overlap smaller → side hit
else         ball.vy = -ball.vy;   // vertical overlap smaller   → top/bottom hit
```
The **overlap** (or penetration depth) is computed on each axis.  The axis with
the smaller overlap is the one the ball hit from — so the velocity component on
that axis is reversed.  This is a standard and robust AABB collision response
technique.

**Win check:**
```cpp
bool anyAlive = false;
for (int i = 0; i < MAX_BRICKS; ++i)
    if (bricks[i].alive) { anyAlive = true; break; }
if (!anyAlive) {
    ++currentLevel;
    if (currentLevel >= NUM_LEVELS) {
        state = GameState::YOU_WIN;
        if (bestTime < 0.0f || elapsedTime < bestTime)
            bestTime = elapsedTime;  // new best time
    } else {
        loadLevel(currentLevel);     // advance to next level
    }
}
```
After every brick collision, the game scans all bricks.  If none are alive, the
player has cleared the level.  If there is a next level, `loadLevel` loads it
(which calls `resetBall`, giving the player a moment before re-launching).  If
all three levels are cleared, the game saves a best time and shows the win screen.

### 7.10  Input Callbacks

**onKeyboard (regular keys, ASCII):**
- Menu state: Enter/Space activates the highlighted menu item; Esc quits.
- Help state: Esc or M returns to menu.
- Playing/Waiting: Space launches the ball; P toggles pause; R restarts;
  M returns to menu from pause or end screens; Esc quits.

**onSpecial (non-ASCII keys: arrow keys, F-keys):**
```cpp
if (key < 256) specialDown[key] = true;
lastInput = InputSrc::KEYBOARD;
```
Sets the key's slot in `specialDown` to true.  `lastInput` switches to
KEYBOARD mode so the paddle starts being driven by arrow keys rather than
the mouse.

**onSpecialUp:**
```cpp
if (key < 256) specialDown[key] = false;
```
Clears the slot when the key is released.  This is how `gameUpdate` knows the
arrow key is no longer held.

**onMouse (button click):**
In the menu, a click calculates which menu item the cursor is over (by
converting the window-pixel Y to world-Y) and activates it.  During gameplay,
any left click launches the ball.

**onPassiveMotion (mouse move, no button held):**
```cpp
lastInput = InputSrc::MOUSE;
float worldX = (float)mx / winW * WORLD_W;
paddle.x     = worldX - paddle.w / 2.0f;
paddle.x     = std::clamp(paddle.x, 0.0f, WORLD_W - paddle.w);
```
Converts the raw window pixel X (`mx`) to a world-space X by scaling with the
ratio `WORLD_W / winW`.  The paddle centre is placed under the cursor by
subtracting half the paddle width.

**onReshape (window resize):**
```cpp
glViewport(0, 0, w, h);
glMatrixMode(GL_PROJECTION);
glLoadIdentity();
glOrtho(0.0, WORLD_W, 0.0, WORLD_H, -1.0, 1.0);
glMatrixMode(GL_MODELVIEW);
glLoadIdentity();
```
`glViewport` maps the OpenGL normalised device coordinates (−1 to +1) to the
actual window pixels.  `glOrtho` sets up a 2-D **orthographic** projection that
maps the logical world (0–800 × 0–600) to the viewport.  The result: no matter
what size the window is, the game always looks like it spans 800 × 600 world
units.  `GL_MODELVIEW` is reset to identity because no 3-D transformations are
needed for a 2-D game.

## 8. sound.h / sound.cpp — Audio System

### sound.h

```cpp
void soundInit();
void soundPlayBrickBreak();
void soundPlayPaddleHit();
void soundPlayWallBounce();
void soundPlayLifeLost();
```
A minimal public interface: one initialisation function and one play function
per game event.  The caller (game.cpp) does not need to know anything about
how audio works internally.

### sound.cpp (macOS implementation)

```cpp
#ifdef __APPLE__
#include <AudioToolbox/AudioToolbox.h>
#include <dispatch/dispatch.h>
```
`AudioToolbox` is Apple's Core Audio framework for playing and recording audio.
`dispatch/dispatch.h` is Grand Central Dispatch (GCD), Apple's threading/
concurrency library.  Both are part of the OS; no installation is needed.

```cpp
static void audioCallback(void* /*unused*/, AudioQueueRef queue,
                          AudioQueueBufferRef buffer)
{
    AudioQueueFreeBuffer(queue, buffer);
    dispatch_async(dispatch_get_global_queue(QOS_CLASS_BACKGROUND, 0), ^{
        AudioQueueStop(queue, true);
        AudioQueueDispose(queue, true);
    });
}
```
This is the **audio thread callback** — called by the OS audio thread when it
has finished consuming a buffer.  Apple's documentation forbids calling
`AudioQueueDispose` from within this callback, so `dispatch_async` schedules
the cleanup on a background thread, where it runs safely after the callback
returns.  `^{ ... }` is a **block** (Apple's closure extension to C/C++).

```cpp
static void playTone(float freqStart, float freqEnd,
                     float duration, float volume, float decay)
{
    const int kRate = 22050;        // sample rate: 22,050 samples per second
    int n = (int)(kRate * duration); // total number of samples
```
22,050 Hz is half the standard CD quality (44,100 Hz).  It is sufficient for
simple game sound effects and uses half the memory.

```cpp
    AudioStreamBasicDescription fmt{};
    fmt.mSampleRate       = kRate;
    fmt.mFormatID         = kAudioFormatLinearPCM;  // raw, uncompressed samples
    fmt.mFormatFlags      = kAudioFormatFlagIsSignedInteger
                          | kAudioFormatFlagIsPacked; // 16-bit, little-endian
    fmt.mBitsPerChannel   = 16;    // each sample is a 16-bit signed integer
    fmt.mChannelsPerFrame = 1;     // mono
    fmt.mFramesPerPacket  = 1;     // uncompressed: one frame per packet
    fmt.mBytesPerFrame    = 2;     // 16 bits = 2 bytes
    fmt.mBytesPerPacket   = 2;
```
This descriptor tells the Audio Queue exactly how the PCM data is laid out in
memory.  The format is: mono, 16-bit signed integers, 22,050 samples per
second, no compression.

```cpp
    AudioQueueRef q;
    AudioQueueNewOutput(&fmt, audioCallback, nullptr, nullptr, nullptr, 0, &q);
```
Creates an **Audio Queue** configured for output (playback).  The queue manages
the low-level audio hardware interaction.  `audioCallback` will be called when
the queue needs more data or when a buffer is done.

```cpp
    AudioQueueBufferRef buf;
    AudioQueueAllocateBuffer(q, (UInt32)(n * 2), &buf);
```
Allocates a buffer large enough for all `n` samples × 2 bytes each.

```cpp
    auto* pcm = (int16_t*)buf->mAudioData;
    float phase = 0.0f;
    for (int i = 0; i < n; i++) {
        float t    = (float)i / kRate;        // time in seconds
        float prog = (float)i / n;            // 0.0 → 1.0 over the duration
        float freq = (freqEnd > 0.0f)
                   ? freqStart + (freqEnd - freqStart) * prog
                   : freqStart;               // linear frequency sweep (or constant)
        float env  = expf(-t * decay);        // exponential amplitude envelope
        phase += 2.0f * PI * freq / kRate;    // advance phase by one sample
        pcm[i] = (int16_t)(sinf(phase) * 32767.0f * volume * env);
    }
```
This generates a **sine wave** with:
- **Frequency sweep**: the pitch linearly interpolates from `freqStart` to
  `freqEnd` over the sound's duration.  If `freqEnd = 0`, pitch is constant.
- **Exponential decay envelope**: `exp(-t × decay)` starts at 1.0 and falls
  toward 0.  Higher `decay` values create a sharper, more percussive sound.
- **Phase accumulation**: instead of computing `sin(2π × f × t)`, the phase is
  accumulated sample-by-sample.  This is numerically stable and correctly
  handles frequency sweeps without phase discontinuities.
- The result is scaled to 16-bit range (−32767 to +32767).

```cpp
    AudioQueueEnqueueBuffer(q, buf, 0, nullptr);
    AudioQueueStart(q, nullptr);
```
Hands the filled buffer to the queue and starts playback.  Control returns
immediately — the sound plays asynchronously on the audio thread.

|------------------------|-----------|---------|----------|-------|-------------------------|
| `soundPlayBrickBreak`  | 800 Hz    | 200 Hz  | 0.12 s   | 18    | Sharp descending chirp  |
| `soundPlayPaddleHit`   | 440 Hz    | none    | 0.06 s   | 28    | Short mid-range blip    |
| `soundPlayWallBounce`  | 700 Hz    | none    | 0.04 s   | 35    | Quick high tick         |
| `soundPlayLifeLost`    | 320 Hz    | 80 Hz   | 0.55 s   | 4     | Slow sad descend        |
